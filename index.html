경험을 쌓는 것에 그치지 않고, 더 나은 구조와 방법을 고민해 온 개발자입니다

저는 12년 이상 Android와 Flutter를 중심으로 다양한 모바일 서비스를 개발해 왔습니다. 초기에는 Android Java 기반의 위치·스트리밍·커머스·IoT 애플리케이션을 개발했고, 이후 Kotlin과 MVVM, AAC, DI 등을 활용한 구조적인 앱 개발을 경험했습니다. 최근에는 Flutter를 기반으로 Android와 iOS를 함께 개발하며 모바일 전반으로 기술 영역을 확장했습니다.

오랜 기간 개발하면서 중요하게 생각해 온 것은 단순히 기능을 완성하는 것이 아니라, 서비스가 지속적으로 운영되고 변경될 수 있는 구조를 만드는 것입니다. 새로운 기술 역시 사용하는 것 자체를 목표로 하기보다는 실제 프로젝트에 필요한지 검토하고, 적용 이후의 안정성과 유지보수성까지 확인하려고 합니다.

아키텍처를 설계하고 대규모 리팩터링으로 구조를 개선합니다

저는 여러 회사에서 앱 전체 개발을 담당했고 Android 개발 파트장과 팀장 역할도 경험했습니다. 기획된 기능을 구현하는 것뿐만 아니라 프로젝트 구조 설계, API 연동, 상태 관리, 성능 개선, 장애 대응, 배포와 운영까지 서비스의 전체 흐름을 직접 다뤄왔습니다.

최근에는 Flutter 기반 EVM·Cosmos 멀티체인 지갑의 아키텍처 설계와 대규모 리팩터링을 담당했습니다. Riverpod·Freezed·Repository 기반 MVVM 구조에서 대형 인증 ViewModel과 중복 블록체인 로직을 분리하고, 자산·인증·트랜잭션 처리의 역할을 정리했습니다. 토큰·NFT, 송금·스왑·브리지·스테이킹, WalletConnect, KYC·리워드 등 서로 연결된 기능의 기존 동작과 변경 영향을 함께 점검하며 구조를 개선했습니다.

특히 지갑 서비스는 개인키와 트랜잭션을 다루기 때문에 일반적인 앱보다 안정성과 보안을 중요하게 생각했습니다. PIN·생체 인증, AES-GCM 기반 보안 저장, 개인키 생명주기 관리와 함께 WalletConnect 세션 복구, Relay 재연결, 서명 처리 등 실제 서비스에서 발생할 수 있는 문제들을 지속적으로 개선했습니다.

체감되는 성능과 안정성을 개선합니다

기능 개발 이후에도 사용자가 느끼는 성능과 서비스 안정성을 개선하는 작업을 중요하게 생각합니다.

개인키 생성 과정에서 반복적으로 발생하던 iOS Keychain 접근을 분석해 계정 정보와 존재 여부를 세션 단위로 캐싱함으로써 한 번의 처리 과정에서 누적되던 6~8회의 보안 저장소 조회를 최소화했습니다.

PBKDF2 연산과 secp256k1 키 파생처럼 연산 비용이 큰 작업은 백그라운드 Isolate로 분리해 PIN 인증, 송금 및 트랜잭션 서명 과정에서 UI 스레드가 멈추거나 프레임이 끊기는 문제를 개선했습니다. BIP44 주소 파생 결과를 캐싱하고 DB 초기화 및 WebView 생명주기, 이미지 사전 로딩 등 앱 전반의 병목도 지속적으로 점검했습니다.

2026.08 집계의 R8 최적화에서는 resources.txt 78.16%·mapping.txt 0.91%·APK 114,872 B 감소와 당시 업데이트·콜드 스타트 검증 범위의 Crash·ANR·주요 플러그인 치명 오류 0건을 확인했습니다. 2026.09에는 규칙·의존성·리소스 정비 후 기존 61번 빌드 대비 DEX 27.71%·Note9 다운로드 예상 16.65% 감소를 확인했습니다. 엔진 차이가 포함된 비교이며 스토어 배포 전입니다. 이미지 디코딩도 표시 크기·기기 픽셀 비율에 맞춰 개선하고 실물 기기에서 비교했습니다.

장애를 수정하는 데서 끝내지 않고 다시 발생하지 않도록 만듭니다

서비스 운영 과정에서는 단순히 발생한 오류를 수정하는 것보다 같은 문제가 다시 발생하지 않도록 만드는 것이 중요하다고 생각합니다.

WalletConnect 요청 복구·Relay 재연결·인증·서명, Provider·비동기 화면 전환의 생명주기, 게임·오디오·카메라·WebView 리소스 해제를 안정화했습니다. 최근에는 Android 저장소 이관 중단·쓰기 실패를 재현하고 새 값의 저장·복호화 확인 후 구형 값을 삭제하도록 보완했습니다. 부분 이관 재시도·갱신 값 보존을 포함한 실물 15개 시나리오와 Dart 테스트 63개를 통과했으며 스토어 배포 전입니다.

2026.08에는 테스트 파일을 1개에서 175개로 확대했고, 이 중 171개를 본인 커밋으로 추가했습니다. 개인 비병합 커밋 150건 중 66건은 결함 수정·QA·안정화 작업입니다. 2026.09 커밋 기준 단위·위젯 241개 및 통합 9개 파일로 회귀 검증을 확대했습니다. 파일 수와 개별 테스트 통과 수를 구분하고, 네이티브 장애는 합성 데이터에 실패 조건을 주입해 별도로 검증했습니다.

또한 Shorebird Code Push를 적용하여 앱스토어 심사를 다시 거치지 않고 Dart 코드와 번역 변경 사항을 배포할 수 있는 운영 환경을 구성하는 등 개발뿐 아니라 출시 이후의 운영 효율도 함께 고려했습니다.

AI로 실행 범위를 넓히고, 검증으로 완성도를 높입니다

최근에는 Gemini·Claude·Codex를 활용하며 문제 분석부터 구현과 검증까지 개발 방식을 확장하고 있습니다. 먼저 서비스의 제약과 변경 범위, 기대 동작을 구체화하고, AI가 제안한 결과를 기존 구조와 보안 요구사항에 맞춰 검토합니다. 최종 판단과 품질에 대한 책임은 제가 맡습니다.

멀티체인 지갑에서는 WalletConnect SDK 재초기화가 로딩 상태를 해제하면서 연결 제안 대기 타이머까지 무효화되는 문제를 추적했습니다. 재초기화 후 페어링 대기 상태를 복구하고, 외부 링크의 오류 전달·동일 링크 재시도·중복 요청 방어를 함께 정리했습니다. 수정 전 실패를 재현한 테스트를 바탕으로 관련 26개 파일의 204개 테스트 통과를 확인했으며, Android 실기기와 iOS XCUITest에서 외부 링크의 제안 미도착 오류와 재시도 동작을 검증했습니다.

Flutter 통합 테스트, Android ADB E2E와 iOS XCTest/XCUITest로 저장소·PIN 호환성과 인증·외부 링크·권한 거부 후 복구를 검증했습니다. 외부 테스트 dApp의 EVM personal_sign 취소·PIN 인증·서명 응답과 복원 주소 일치를 확인했습니다. 자동화와 직접 확인할 항목을 구분하고, AI가 만든 구현도 테스트·실제 화면·기대 결과를 대조해 판단합니다.

경험을 바탕으로 팀과 서비스의 개발 품질을 높이고 싶습니다

저는 오랜 경력이 모든 것을 알고 있다는 의미라고 생각하지 않습니다. 다양한 프로젝트와 개발자들을 경험하면서 오히려 서로 다른 방식과 경험에서 배울 것이 많다는 점을 배웠습니다.

제가 가진 강점은 새로운 환경에서도 빠르게 서비스 구조를 이해하고, 필요한 기능을 구현하는 동시에 문제가 발생하는 원인을 찾아 구조적으로 개선할 수 있다는 점입니다. Android Native에서 Flutter까지, 위치 기반 서비스와 커머스, 미디어, IoT, 헬스케어 그리고 블록체인 지갑까지 서로 다른 도메인을 경험하면서 새로운 기술과 비즈니스를 빠르게 이해하는 역량도 쌓았습니다.

앞으로도 사용자의 문제를 이해하고, AI를 활용해 해결 방법을 빠르게 구현하며, 안정성·성능·사용자 경험을 검증하는 개발자로 기여하고 싶습니다. 축적한 모바일 개발 경험과 검증 방법을 팀에 공유하고, 출시 이후의 개선까지 이어지는 제품 개발을 함께하겠습니다.
